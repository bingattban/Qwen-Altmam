# التمام اليومي (AlTamam AlYawmi)

تطبيق مكتبي محلي متكامل لنظام **Windows** يعمل بالكامل **دون اتصال بالإنترنت (100% Offline / Zero CDN)** لإدارة القوة البشرية، التحضير اليومي والشهري، التنقلات الداخلية والخارجية، الفصل والاسترجاع، التقارير التاريخية، وسجل العمليات المؤمّن.

بُني التطبيق بواجهة عربية أصيلة من اليمين إلى اليسار (**RTL**) تجمع بين مضيف **WPF (.NET 10)** ومحرك العرض المحلي المعزول **Microsoft Edge WebView2**، مع قاعدة بيانات علائقية مشفرة بالكامل عبر **SQLCipher (AES-256)** ومفاتيح تشفير محمية بواسطة **Windows DPAPI**.

## أبرز المميزات والخصائص المعمارية

* **عمل محلي كامل ومعزول عن الشبكة (Strict Offline Isolation):**
  يربط التطبيق واجهة المستخدم بنطاق افتراضي محلي مقفل (`https://manger.adwas.example/`) مع سياسة أمان محتوى صارمة (`Content-Security-Policy: default-src 'none'; connect-src 'none'`)، ويحظر أي اتصال شبكي خارجي أو تحميل خطوط/مكتبات من الإنترنت.
* **تشفير كامل لقاعدة البيانات وحماية المفاتيح:**
  تُحفظ جميع البيانات في قاعدة بيانات `SQLite` مشفرة عبر `SQLCipher`، ويُشتق مفتاح التشفير العشوائي (`32-byte`) ويُحمى محلياً لحساب مستخدم Windows عبر `DPAPI` (`db.key.protected`)، مع دعم حزم مفاتيح الاسترداد المحمولة المشفرة (`AES-GCM` + `PBKDF2-SHA256` بـ 600,000 تكرار) بامتداد `.altrecovery`.
* **ثبات التاريخ وعدم قابلية التعديل بأثر رجعي (Temporal & Historical Integrity):**
  يعتمد النظام على معرفات داخلية دائمة غير قابلة لإعادة التدوير (`PersonId`, `SiteId`, `StatusId`, `AssignmentId`, `MovementId`, `UserId`)، بحيث لا يُربط أي سجل تاريخي بالاسم أو «الرقم (ع)» القابلين للتعديل، مع حفظ لقطات تاريخية مؤرخة (`Snapshots`) لأسماء الأفراد والمواقع والحالات في كل واقعة تحضير أو نقل.
* **سجل تدقيق غير قابل للمسح مترابط بالتجزئة (Tamper-Evident Audit Chain):**
  تُسجَّل كل عملية كتابة أو تعديل في جدول `AuditEvents` داخل نفس المعاملة (`ACID Transaction`)، ويرتبط كل قيد ببصمة `SHA-256` تشمل بيانات العملية وبصمة القيد السابق (`PriorEventHash`) لكشف أي تلاعب خارجي، مع دعم طبقة العرض والتصحيح الظاهري (`AuditLogPresentationEdits`) دون المساس بالأدلة الأصلية.
* **التحضير التلقائي المجدول والاستدراك الذكي (Automated Carry-Forward & Catch-Up):**
  يعمل مجدول خلفي مستقل داخل مضيف `WPF` لتنفيذ التحضير التلقائي في الوقت المحدد إدارياً (افتراضياً `08:00` صباحاً) بنسخ حالات اليوم السابق لغير المحضرين أو تطبيق الحالة الافتراضية المعتمدة، مع استدراك تلقائي للأيام الفائتة عند إيقاف تشغيل الجهاز، وحماية ضد التلاعب بساعة النظام (`Clock Rollback Detection`).
* **معاينة إلزامية من خطوتين ومنع التكرار (Two-Step Preview & Idempotency):**
  تتطلب جميع العمليات الحساسة (التحضير، تعديل الحالة، النقل، الفصل، الاستيراد، التصفير الكامل) إصدار رمز معاينة لمرة واحدة (`PreviewToken`) مرتبط بالمستخدم والبيانات وإصدار الصفوف (`RowVersion`)، بالإضافة إلى إيصالات عدم تكرار العمليات (`MutationReceipts`).

## الأقسام والشاشات الرئيسية

يتكون التطبيق من **4 أقسام رئيسية** تضم **69 هوية مسار** تشمل الشاشات والنوافذ المنبثقة والعمليات (من بينها التقرير الموحد `screen_025` وإضافة فرد داخل تعديل الأسماء `screen_070`، بينما المعرّف `screen_020` ملغى):

| القسم الرئيسي | الوصف والوظائف الأساسية |
| :--- | :--- |
| **1. الرئيسية (`Dashboard`)** | عرض عدادات القوة النشطة وإحصائيات الحالات اليومية، فلترة الكشف اليومي حسب الموقع أو الحالة أو البحث، عداد تنازلي لموعد التحضير التلقائي، ونافذة مستقلة لمراجعة وتصحيح «المحضّرين تلقائياً». |
| **2. التمام الشهري (`MonthlyAttendance`)** | شبكة حضور شهرية تفاعلية بثبات الأعمدة التعريفية الأربعة الأولى، عرض الحالات والتنقلات والفصل والعودة بالألوان والرموز في كل خلية يومية، نافذة تفاصيل اليوم وسجل تعديلاته، استعراض أرشيف الأشهر السابقة، وتصدير الكشف الشهري إلى ملف Excel (`XLSX`). |
| **3. الإدارة (`Administration`)** | **إدارة القوة:** التحضير الفردي والجماعي ومسودات التحضير، إضافة الأفراد وتعديل الأسماء والأرقام (ع) (`screen_070`) مع كشف تطابق الهويات المؤرشفة، النقل الداخلي والخارجي وأرشيفهما، فصل الأفراد بمهلة تأكيد إلزامية (5 ثوانٍ) وأرشيف المفصولين، التقرير الشامل الموحد للفرد أو المجموعة (`screen_025`) وتصديره إلى Excel، والتصحيح الاستثنائي لليوم المغلق.<br>**الحالات والمواقع:** إضافة وتعديل وتعطيل المواقع وحالات التحضير مع حفظ تاريخ الأسماء.<br>**الكشوفات:** استيراد الأفراد من Excel (`XLSX`) على ثلاث مراحل (تحليل، معاينة، اعتماد) مع تصدير تقارير الأخطاء، وتعديل هيكل أعمدة الكشف.<br>**المستخدمون وسجل العمليات:** إدارة الحسابات المحلية (`Argon2id`)، وتصفح سجل العمليات مع التحقق من سلامة السلسلة. |
| **4. الإعدادات (`Settings`)** | ضبط الحالة الافتراضية وأوقات التحضير التلقائي وقفل التمام اليومي، تحديد المجلد المشترك للنسخ الاحتياطي وتقارير Excel، جدولة النسخ الاحتياطي التلقائي أو إنشاء نسخة مشفرة فورية، فحص سلامة قاعدة البيانات ونسخ الاستعادة، وتصفير بيانات البرنامج بالكامل (للإدارة العامة فقط). |

## الصلاحيات والأدوار (RBAC)

يطبق النظام مصفوفة صلاحيات صارمة في طبقة `#C` الخلفية (`WebView2BridgeDispatcher` والخدمات) ولا يعتمد على إخفاء أزرار الواجهة فقط:

| الدور | المسمى العربي | الصلاحيات الأساسية |
| :--- | :--- | :--- |
| `GeneralAdministration` | **الإدارة العامة** | الحساب المؤسس المستقل عن كشف القوة (حساب واحد فقط يُنشأ عند التهيئة الأولى)؛ يمتلك كامل الصلاحيات بما فيها إدارة حسابات الإدارة العادية والمشرفين، التصحيح الاستثنائي، تعديل/إخفاء العرض في سجل العمليات، وتصفير بيانات البرنامج بالكامل. |
| `OrdinaryAdministration` | **الإدارة العادية** | يرتبط بفرد نشط في كشف القوة؛ يدير عمليات القوة، المواقع، الحالات، الكشوفات، إعدادات التحضير والنسخ الاحتياطي، التصحيح الاستثنائي، تعديل العرض في سجل العمليات، وإدارة حسابات المشرفين فقط. |
| `Supervisor` | **مشرف** | يرتبط بفرد نشط في كشف القوة؛ ينفذ العمليات اليومية (التحضير، التنقلات، الفصل، التقارير، الاستيراد/التصدير، النسخ الاحتياطي اليدوي، والاطلاع على سجل العمليات للقراءة فقط) دون صلاحية إدارة المستخدمين أو تعديل سجل العمليات أو تصفير البيانات. |

* **إدارة الجلسات والأمان:** تُحفظ كلمات المرور بتجزئة `Argon2id` (`MemorySize = 64 MB`, `Iterations = 3`, `Parallelism = 2`)، ويُقفل الحساب مؤقتاً لمدة 15 دقيقة بعد 5 محاولات دخول خاطئة. تنتهي الجلسة تلقائياً بعد 5 دقائق من الخمول الفعلي، وتُلغى جلسات وحساب أي مستخدم تلقائياً فور خروجه من القوة النشطة (نقل خارجي، فصل، أو أرشفة).

```text
AlTamam.slnx
├── Directory.Build.props             # إعدادات البناء الموحدة (Nullable, TreatWarningsAsErrors, Deterministic)

│   ├── AlTamam.Contracts/            # عقود جسر WebView2، رموز الأخطاء القياسية (24 رمزاً)، وأحداث تحديث الواجهة (13 حدثاً)
│   ├── AlTamam.Infrastructure/       # سياق قاعدة البيانات المشفرة (SQLCipher)، مشغل الترحيلات (V001–V009)، مخزن مفاتيح DPAPI، وفحص/تجهيز النسخ الاحتياطية
│   ├── AlTamam.Application/          # موزع الجسر (WebView2BridgeDispatcher)، كتالوج الإجراءات، خدمات القوة والتحضير والتنقلات والتقارير والتدقيق، والمجدولات

│   └── AlTamam.WebUI/                # أصول الواجهة المحلية (HTML5, CSS3 RTL, Vanilla JS) وعقد الإجراءات والشاشات (action-manifest.json, screen-manifest.json)
├── tests/
│   └── AlTamam.Tests/                # اختبارات التكامل، الأمان، التشفير، الترحيلات، والأداء (xUnit)
├── build/                            # سكربتات التحقق من العقود والهيكل (manifest-guard.py, validate-ui-shell.py, validate-layout.py) وملف إعداد المثبت (Inno Setup)
└── docs/                             # وثائق المعمارية (ADR)، تتبع المتطلبات، سجل المخاطر، وأدلة الاسترداد والأمان
```

## التقنيات والمكتبات المستخدمة

* **بيئة التشغيل والواجهة المكتبية:** `.NET 10.0` (`net10.0-windows`) + `WPF` + `Microsoft.Web.WebView2` (`1.0.2903.40`)
* **قاعدة البيانات والتشفير:** `Microsoft.Data.Sqlite.Core` (`9.0.2`) + `SQLitePCLRaw.bundle_e_sqlcipher` (`2.1.10`)
* **أمان كلمات المرور والمفاتيح:** `Konscious.Security.Cryptography.Argon2` (`1.3.1`) + `System.Security.Cryptography.ProtectedData` (`9.0.2` - Windows DPAPI)
* **توليد واستيراد ملفات Excel:** توليد وقراءة `Office Open XML (.xlsx)` محلياً عبر `System.IO.Compression` و`System.Xml` دون مكتبات خارجية، مع كتابة النصوص كخلايا نصية مباشرة (`inlineStr`) لمنع حقن الصيغ (`Formula Injection`).
* **إطار الاختبارات:** `xUnit` (`2.9.2`) + `Microsoft.NET.Test.Sdk` (`17.12.0`) + اختبارات واجهة مبنية على `Node.js`.

## متطلبات التشغيل والبناء

1. نظام تشغيل **Windows 10 / 11** (معمارية `x64` أو `x86`).
2. حزمة تطوير **.NET 10 SDK**.
3. Runtime مكون **Microsoft Edge WebView2** (مُضمَّن محلياً للتثبيت الصامت دون إنترنت في حزم التوزيع تحت `Prerequisites/MicrosoftEdgeWebView2RuntimeInstaller.exe`).
4. (اختياري لبوابات الفحص والاختبارات الإضافية): **Python 3** و**Node.js**.

### أوامر البناء والاختبار

```powershell
# 1. استعادة الحزم
dotnet restore AlTamam.slnx

# 2. بناء الحل بالكامل في وضع Release
dotnet build AlTamam.slnx -c Release --no-restore

# 3. تشغيل حزمة اختبارات الوحدة والتكامل والأمان والأداء
dotnet test tests/AlTamam.Tests/AlTamam.Tests.csproj -c Release --no-restore
```

### أوامر التحقق من العقود والواجهة (CI Gates)

```powershell
# التحقق من تطابق عقد الإجراءات (action-manifest.json) مع الكود والواجهة وسياسة CSP
python build/manifest-guard.py

# التحقق من سلامة هيكل الواجهة ومسارات الشاشات وقواعد عدم تسريب الملفات الحساسة
python build/validate-ui-shell.py
```

### أوامر النشر والفحص الذاتي للحزمة

```powershell
# نشر نسخة Windows x64
dotnet publish src/AlTamam.DesktopHost/AlTamam.DesktopHost.csproj -c Release -r win-x64 -o publish/win-x64

# التحقق من سلامة ملفات النشر والمكتبات الأصلية (SQLCipher & WebView2Loader)
python build/validate-layout.py publish/win-x64

# تشغيل الفحص الذاتي الصامت لهيكل الملفات ومسارات التخزين
./publish/win-x64/AlTamam.DesktopHost.exe --layout-selfcheck
```

## أوضاع التخزين والنسخ الاحتياطي

يدعم التطبيق وضعين لتخزين البيانات (`AppDataLayout`):
1. **الوضع المثبّت (Installed Mode):** تُحفظ قاعدة البيانات المشفرة ومجلد `WebView2` تحت مسار المستخدم المحلي `%LOCALAPPDATA%\AlTamam\altamam.db`، ولا تُوضع أي ملفات قابلة للكتابة داخل `Program Files`.
2. **الوضع المحمول (Portable Mode):** تُحفظ البيانات في مجلد `data\` بجوار الملف التنفيذي مباشرة.
3. **الترحيل لجهاز آخر:** نسخ قاعدة البيانات الاحتياطية وحدها ليست بديلاً عن حزمة الاستعادة المشفرة المستقلة (`.altrecovery`) عند نقل البيانات إلى جهاز Windows آخر، نظراً لارتباط مفتاح `DPAPI` بحساب وجهاز Windows الأصلي.
