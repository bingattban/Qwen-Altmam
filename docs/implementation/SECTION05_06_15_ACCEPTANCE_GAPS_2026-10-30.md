## Change contract (05.04)

- **Owning layer:** existing Phase 15 packaging/Windows acceptance and Phase 01 CI, plus local Python integrity scripts. No new phase, route, schema or role.
- **DTO/contracts:** `BUILD_METADATA.json` adds `sourceHeadSha` without altering business DTOs or bridge actions. `commit` remains the *actual checkout SHA* used to compile the code, not an invented alias to the PR head. For PRs, both SHA values are intentionally distinct when GitHub tests its merge ref.
- **Input validation:** strict 40-hex Git SHAs, exact 2 expected packages for the declared x86/x64 target, SHA-256 digest, byte sizes, runtime and metadata; rejects stale/tampered/partial outputs. Unit tests include corrupted ZIP/EXE, invalid/duplicate checksum, wrong architecture, wrong commit/head, missing file and bad byte count.
- **Authorization / error codes:** no change to C# authorization, user session, actions, or canonical application error codes. CI verifier exits nonzero and fails packaging before uploads.
- **Transaction / rollback:** no database writes or migrations. On failure GitHub blocks further package uploads/merge. Existing package tests preserve AppData and clean up only their randomized test sentinel.
- **Tests:** `build/test-release-artifact-provenance.py` is executed on BOTH independent Core and Release Windows preflights. Real per-package byte verification runs in EACH x86/x64 Release matrix job. Real Windows WebView2 smoke now exercises the actual packaged binaries three times per architecture, not an HTML mock.
- **Outstanding NOT RUN / manual gates:** real user interaction, forbidden actions and keyboard accessibility across every screen, physically unplugged network, clean Windows x86 hardware, cross-PC restoration and power interruption. A green CI run never implies these have passed.
