## 04.01 — Dashboard and automatic register

- **Code present:** `src/AlTamam.WebUI/assets/js/functional-screens.js` reads `GetDashboardSummary` and `QueryDailyRoster`, filters by site/status and opens the automatic register via the counter. Actual saved-status cards include Present. No duplicate completion/unprepared primary counters. Opening the dashboard/register is read-only.
- **Code present:** `src/AlTamam.Application/Bridge/DailyMonthlyReadService.cs` reads committed auto records using durable automatic idempotency keys, retaining automatic origin in the register after an authorized same-day manual revision. Search/site/date/current status/source are projected from saved data.
- **Code present since PR #129:** per-person status selector, selected checkboxes, Select Page, common bulk target status (100 maximum), native `attendanceReview` modal, `PreviewAttendanceChange(mode=revise)`, and one atomic `ReviseTodayAttendance` command per confirmed selection. Server rechecks each person's status/version/assignment and records attendance revisions and audit events.
- **Hardened in this review branch:** pending selections cannot be silently cleared with «إلغاء التحديد» or discarded by pressing «إغلاق», Escape, or clicking the register backdrop. The operator must explicitly accept the discard prompt; refusal preserves the selection and never commits attendance. Register close is blocked while a confirmed operation is still in flight. This does not alter the established preview/commit path.

## 04.02 — Monthly attendance

- **Code present:** `renderMonthly` in `functional-screens.js` builds read-only day 1..month-end columns and abbreviated weekdays, sticky identity columns, page navigation, an archive month/year picker, and `لا يوجد أرشيف لهذا الشهر` for missing periods. The current day scrolls toward the fixed columns without changing column order.
- **Code present:** `DailyMonthlyReadService.MonthlyGridAsync` uses date-qualified assignments and historical identity snapshots; days before original admission have no generated attendance. It preserves recorded attendance on transfer days while adding movement labels to source/destination projections.
- **Still to validate on actual Windows/WebView2:** sticky headers/RTL scroll alignment, the initially visible current-day position, keyboard access, large 2,000–10,000-person pagination, and day-by-day transfer presentation across month boundaries.
