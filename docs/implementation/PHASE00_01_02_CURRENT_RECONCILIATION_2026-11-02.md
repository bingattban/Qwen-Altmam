## المرحلة 02 — SQLCipher والترحيلات والسجل التاريخي

- **الموجود:** مزود `SQLitePCLRaw.bundle_e_sqlcipher` المعتمد، `PRAGMA cipher_version`، WAL، مفتاح 32 بايت، DPAPI لحساب Windows، نسخ إنقاذ مشفرة قبل الترحيل، هويات مؤرخة، قيود عدم تداخل التعيينات، سجل تدقيق غير قابل للتعديل. V001–V012 مُضمّنة وثابتة دون إعادة كتابة.
- **النقص المكتشف:** `SchemaMigrationRunner.VerifyRecordedHashes` كان يمر على بصمة SHA-256 `NULL` أو سجل نسخة مفقود، كما أن فتح قاعدة بيانات عند رقم المخطط الحالي لا يعيد فحص بصمات نسخ الترحيل المطبقة.
- **التصحيح في هذه الدفعة:** جعل غياب/تغيير اسم أو SHA-256 الخاص بأي نسخة V002+ إخفاقاً صريحاً، واستدعاء فحص البصمات أيضاً عند فتح قاعدة بيانات موجودة ومحدثة. V001 استثناء مقصود لأنها سابقة لإضافة عمود البصمة. لا يوجد تعديل على ملف SQL قديم أو إصدار مخطط أو مفتاح أو بيانات مستخدم، ولا إصلاح صامت لسجل متلاعب به.
- **الاختبارات المضافة أولاً:** فتح SQLCipher موجود بعد حذف سجل ترحيل أو حذف بصمته أو تغييرها يرفض البدء؛ فتح سجل صحيح يحتفظ بالإعدادات وسلامة الملف. الاختبارات تعمل داخل مشروع Phase 02 المستقل في Core وRelease قبل التغليف.
- **حالة القبول:** اجتياز CI لهذه الدفعة شرط لإعلان إغلاق الفجوة البرمجية. الاستعادة الذرية المدمرة على جهاز آخر `RestoreDatabaseAtomically` ما زالت **معطلة** ولا تُفعّل بلا دليل مستقل وموافقة المالك.
