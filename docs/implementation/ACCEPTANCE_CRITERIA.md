# AlTamam — Acceptance Criteria (directive §22 deliverable set)

Status: **NEW 2026-10-23** (created to close the §22 doc-set gap; the file was previously
absent from `docs/implementation/`). This file defines what "accepted" means per step and
per final release. It changes no production code and no manifest data.

## 1. Definition of DONE — every step (directive §22, verbatim criteria)

A phase/step may be marked DONE only when ALL eight conditions hold:

1. **Spec mapped to source** — requirement clause → file/action/route recorded in
   REQUIREMENTS_TRACEABILITY.md (or MANIFEST_ACTION_COVERAGE.md for action-level work).
2. **Complete code committed** — full files on the working branch; `git status` clean; no
   partial patches, stubs, TODO-only services, fake handlers or silent no-ops (§2.3).
3. **Tests ACTUALLY executed and passed at the exact SHA** — real run output (trx/artifact)
   tied to the commit SHA being accepted. Authored-but-unrun tests are NOT RUN, never PASS.
4. **Regression/security checks relevant to the change passed** — manifest guard, SQL/RBAC/
   egress scans, migration integrity as applicable to the diff.
5. **Windows CI passed where relevant** — GitHub Actions windows-latest run URL + run ID +
   conclusion; browser preview is never Windows desktop proof (§2.4).
6. **No policy or data-integrity regression** — invariant map rows unchanged or changed with
   explicit owner-approved ledger entry.
7. **Review packet delivered** — §2.6 compact packet (mapping, files, SHA, PR, CI run, test
   outputs incl. failures, security notes, next gate).
8. **Owner approved the gate** — recorded in IMPLEMENTATION_LEDGER.md "Owner approval" column.

Any unmet condition ⇒ status stays IN PROGRESS / BLOCKED / NOT RUN — with an explicit
"NOT RUN" field listing what did not execute and why (capability gaps are reported, never
hidden).

## 2. Ledger entry schema (machine-readable fields per step)

Every IMPLEMENTATION_LEDGER.md row/batch must record these fields (template):

| Field | Content rule |
|---|---|
| Phase/Step ID + topic title | Exact English/Arabic topic title pair |
| Requirement clause ref | Directive section + traceability row id(s) |
| Impacted manifest actions/routes | Action names (from action-manifest.json) and routeKeys (from screen-manifest.json); "none" allowed but stated |
| Preconditions & dependent steps | Gate states, prior SHAs, owner decisions |
| Scope + ≤10 affected/new files per batch | Exact relative paths with NEW/MODIFIED/MOVED/DELETED + necessity; oversize batches disclosed and split into substeps |
| Schema changes / migration version | VNNN filename + forward-only note, or "none" |
| Tests required | Unit / integration / security / Windows-UI acceptance, each with vehicle path |
| Commit SHA / PR number / CI workflow run ID + conclusion | Real identifiers or explicit "none yet" |
| Verified artifacts | What was actually executed here (commands + results) |
| Explicit NOT RUN fields | Everything not executed, with reason (e.g. no dotnet SDK in sandbox) |
| Owner approval decision / next-step eligibility | PENDING / APPROVED / REJECTED + which step unlocks |

## 3. GitHub workflow acceptance criteria (applies to every future workflow edit)

- Syntax validated before merge (`yaml.safe_load` or actionlint where available); runner
  images limited to documented GitHub-hosted labels (`windows-latest`) — no assumed tools:
  every non-preinstalled tool is explicitly installed via a pinned approved action/version.
- Failures propagate: no `|| true`, no `continue-on-error: true`, no bash pipes that mask
  exit codes without pipefail; advisory/test gates throw nonzero on findings.
- The exact solution containing the WPF executable AND the test project is restored and
  built (`AlTamam.slnx` covers `src/AlTamam.DesktopHost` + `tests/AlTamam.Tests` — verified).
- Acceptance runs `dotnet test` with trx result upload — build alone is never acceptance.
- A CI job enforces the 69-route/90-action manifest contract (`build/manifest-guard.py`;
  now wired into BOTH workflows as of the §22 audit).
- Coverage/result reports generated by the suite are uploaded; artifacts contain logs and
  hashes only — no raw personal data, DB files, or secrets (§2.10 hygiene).
- Release pipeline produces BOTH distributables (Portable ZIP + Inno Setup installer) plus
  SHA-256 checksums + build metadata (`build/make-metadata.py`).
- Publishing is gated: builds on push/PR produce RC artifacts only; GitHub Release creation
  requires manual dispatch after Phase 16 gate + owner approval (verified: no auto-publish
  step exists in either workflow).
- If a remote runner cannot be reached or a pinned package install fails, the job FAILS and
  the evidence template records BLOCKED explicitly — never a silent skip.

### 3a. Known false-green risks found & fixed in the §22 audit (2026-10-23)
1. `windows-release.yml` preflight used `cmd | tee file` then `! grep -q …` under default
   bash: restore/list failure exit codes were masked by the pipe. Rewritten to pwsh with
   `$LASTEXITCODE` guards + `Select-String` throw.
2. Category filters (`Category=Unit|Persistence|Security|Performance`) matched ZERO tests
   (no `[Trait("Category",…)]` exists anywhere in `tests/`), so those steps would have
   exited 0 having run nothing. Replaced by a single FULL-suite `dotnet test` plus a trx
   counter guard that throws if total executed tests < 1.
3. `clean-windows-acceptance` ran `--filter Category=Acceptance` for tests that do not
   exist ⇒ guaranteed vacuous green. Now hard-fails with an explicit BLOCKED message until
   real acceptance tests are authored.
4. `windows-build.yml` (push/PR gate) did not enforce the manifest contract at all. Added
   `manifest-contract` job running `python build/manifest-guard.py` ahead of compilation.

## 4. Final acceptance (release) criteria — FINAL_ACCEPTANCE_REPORT.md completion rules

The report may flip from NO-GO to GO only when: freeze SHA established (§16.01); independent
verifier workspace provisioned (§16.02); EVERY §3 matrix row shows PASS with retained CI run
URLs at the frozen SHA — zero rows left NOT RUN/UNVERIFIED in critical areas; both packages
rebuilt at FREEZE_SHA with hash-equality across two machines (§16.05); offline clean-machine
smoke matrix green including uninstall-preserves-data (§15.06 carry-over); external review
triage closed (§16.06); owner signature present (§16.08). Until then the standing
recommendation remains **NO-GO** (current state, honestly recorded).
